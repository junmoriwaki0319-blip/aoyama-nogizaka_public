## 本日 audit の方法論

### Lighthouse
- Version: **13.2.0** (npx --yes lighthouse, npm cache 経由)
- 共通フラグ: `--output=json --chrome-flags="--headless --no-sandbox" --quiet --max-wait-for-load=60000`
- mobile: `--form-factor=mobile`
- desktop: `--preset=desktop`
- tap-targets ファイル: `--form-factor=mobile --only-audits=tap-targets,target-size`
  - **Lighthouse 13.x で `tap-targets` audit は削除済み**。実際に出力される audit は `target-size` のみで、これは axe-core `target-size` ルール委譲、**WCAG 2.5.8 Level AA = 24×24 CSS px** 判定。
  - 表の "target-size violations (24×24 AA)" 列は `audits.target-size.details.items.length`。
- Chrome kill 例外について: 全 LH 実行で `chrome-launcher` の `Launcher.kill` がスタックトレースに出るが、JSON は完全に書き出され全カテゴリスコアが取得できている。Windows + LH13 + headless Chrome の既知の terminate ノイズと判断、続行に支障なし。

### Playwright (44×44 enhanced)
- WCAG 2.5.5 Level AAA 相当 (44×44 CSS px) の独立計測。LH 13.x では拾えないため別ジョブで補完。
- Viewport: 375×667 (iPhone SE), Chromium headless
- 対象セレクタ: `a, button, input[type=button|submit|reset], [role=button], [role=link], [onclick], label[for]`
- 除外: display:none / visibility:hidden,collapse / opacity:0 / 0×0 矩形
- 計測スクリプト: 4/21 baseline の `audits/measure-tap-targets.js` を作業ツリーに取得し、PAGES に 13 番目の URL 追加 + 出力を slug 別 JSON 化する最小編集を施し実行。スクリプト自体は本 commit に含めず、実行後に作業ツリーから削除。
- per-page JSON: `tap-targets-44x44-{slug}.json`（各 URL の violations 配列、deficit、selector path 等を保存）

### axe-core CLI
- Version: **4.11.3** (npx --yes @axe-core/cli)
- WCAG 2.1 / 2.2 AA 相当のルールセットで headless Chrome 実行
- 表の "axe rules" = violations 配列の長さ (該当ルール数)、"axe nodes" = 全 violations の nodes を合算 (4/21 summary と同手法)

### 4/21 vs 5/5 の限界
- 4/21 は LH **mobile only**（desktop は無し）のため desktop-perf の Δ は計算不可。
- 4/21 は target-size / 44×44 専用測定が baseline summary に含まれていなかったため、これらの Δ も省略。
- axe nodes の差分は 4/21 と同じカウント方法 (rule × node) で計算。
